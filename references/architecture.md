# 架构：module、缝、调用姿势

给**改它的人**读。

## 目的与全景

```text
成品 ─┐
      ├─→ 枚举核对地图（脚本）─→ 模型/子代理在独立上下文里对照 ─→ fact-audit.json ─→ 交付门
来源索引 ┘                                                        ↑
                                                          盲区从来源索引抄过来
```

它只回答两件事：**成品相对来源漂移了吗**、**加工时算错写错了吗**。

## 模块表

| module | 它是什么 | 拥有什么（唯一主人） | 接口 | 不做什么 |
|---|---|---|---|---|
| `SKILL.md` | 触发面与全景 | 何时进、最小代价的三样东西、四类事实的裁定方式、交付门规则 | 模型入口 | 不复述契约字段 |
| `contracts/fact-audit.schema.json` | 产出契约**权威** | 疑点清单的字段、枚举、必填 | 被校验器读；被调用方引用 | 不是文档；不解释怎么裁定 |
| `scripts/enumerate-surface.mjs` | 枚举核对地图 | 「成品里哪些东西会被读者当事实」的**机械提取**：数字（含中文数字与成数）、引号原话、语气强度词；行首序号不算事实 | CLI `<成品> [--out] [--text]` | **不做判断**：不说哪条成立、不说该不该核 |
| `scripts/validate-fact-audit.mjs` | **唯一校验器 + 交付门** | 结构校验、成品是否在核查后被改过、盲区是否原样抄过来、`--gate` 的三条门规则 | CLI `<audit.json> [--gate] [--text]` | 不判断裁定对不对（那是人的事）；不自己找疑点 |
| `evals/run.mjs` | 判据的可执行形态 | 回归：枚举不漏、序号不算事实、交付门、一致性与盲区。**条数由 runner 自己数并打印，本文件不复述数字** | `node evals/run.mjs` | 不是规格来源；**验不了语义那一半**（有没有真抓到漂移） |
| `GOTCHAS.md` | 候选经验 | 现象／原因／行为修正／证据／状态 + 属于哪个 module | 人读 | 不存过程日志 |

## 缝

| 缝 | 谁交给谁 | 内容 |
|---|---|---|
| 上游 → 本模块（**输入**） | 调用方 Skill → 本模块 | ① 成品路径 ② 一份 `source-index/2.0.0` ③ 输出位置。**不给作者的推理过程**（见下） |
| 本模块 → 下游（**输出**） | 本模块 → 调用方 / 报告 / 审阅 | `fact-audit.json`：疑点清单 + 盲区 + 成品哈希 |
| 与 `planners-source-index` 的边界 | 来源索引 → 本模块 | 来源索引管「有哪些来源、原文在哪、哪些没读到」；**派生关系（一条结论由哪几条来源算出）留在本层**，不上移 |
| 与 claim 审计的边界 | `planners-quali-box` 的 `claim-ledger` ↔ 本模块 | claim 审计问「解释是否成立」；事实核查问「展示出来的东西是否属实」。**两份 SKILL.md 各写一句，不许互相冒充** |
| 与审阅内核的边界 | 本模块 ↔ `planners-review-core`（B8） | 本模块只**写文件**；要不要把疑点送给人逐条裁定，是审阅面的事 |

## 调用姿势（上游 Skill 照这个派单）

```text
父 Skill：做完成品后，派一个子代理，给它四样东西 ——
  ① 本 Skill 的 SKILL.md 路径
  ② 成品路径
  ③ 来源索引路径
  ④ 输出路径（work/fact-audit.json）
不给：预期答案、作者的设计意图、任何"这里应该没问题"的暗示。

子代理：enumerate → 逐条对照/复算 → 写 fact-audit → 跑 --gate → 回报"放行/不放行 + 哪几条"
父 Skill：拿到不放行就回去改，改完重跑（成品哈希变了，旧核查自动失效）
```

**为什么必须独立上下文**：模型自查等于没查（quanti 0.3.0 已经栽过一次：代理诚实地把一段自述填进 `user_confirmation.verbatim`，而机器只检查了「非空」）。这道检查唯一的强制力就来自「跑它的人没看过作者的推理」。

## 同一件事的两个决定点（不是两个真相源）

- **疑点的"有没有"** 由脚本枚举 —— 宁多勿漏，漏一个的代价是「这条永远没人查」；
- **疑点的"成不成立"** 由模型/子代理裁定 —— 语义判断，脚本不碰。

两者都不能单独决定交付：门看的是**裁定记录**，不是枚举数量，也不是模型的自述。

## 枚举器的能力边界（必须知道）

2026-09-26 的第二次漂移跑测（`b2-forward-test/round2`，四处都不含新数字）证明了一件事，也划出了一条线：

- **它指得到的**：写出来的数字、引号原话、语气强度词（现在含「普遍 / 大多数 / 多数 / 主流 / 几乎」）。扩充词表能把「消费者**普遍**对价格敏感」这类从"零命中"变成"指得到"。
- **它永远指不到的**：**成品里"少写了什么"** —— 同比口径被删掉、两条原话只引了对结论有利的那一条、把「一位受访者」写成「多位受访者」。这些在成品里**没有对应的字面**，枚举器无从下手。

**所以：地图不是检查的全部。** 检查者必须**回读来源**，把"来源里有、成品里没有"当成一等漂移（`drifting` 的限定条件丢失与选择性引用，`mismatch` 的主体放大）。**不要指望靠扩充词表解决这一类** —— 那是把语义问题伪装成枚举问题。

## 动了 X 会牵连什么

| 你要改 | 该动哪里 | 会牵连什么 |
|---|---|---|
| 枚举规则（漏了什么） | `scripts/enumerate-surface.mjs` | `evals/run.mjs` 的"抓全"断言立刻要跟着加样例；否则规则退化了没人知道 |
| 交付门规则 | `scripts/validate-fact-audit.mjs` 的 `checkGate` | 四个调用方 Skill 的完成标准要同步（它们引用了门的行为） |
| 产出字段 | `contracts/fact-audit.schema.json` | 校验器自动跟着变；调用方的 Stage 文档要改 |
| 门里那条「盲区必须抄过来」 | 本模块 + 来源索引的 `blind_spots` 定义 | 两处的盲区语义必须一致 —— 这是跨两个公共模组的缝 |

## 已知重复（诚实登记）

`scripts/validate-fact-audit.mjs` 里那段通用结构校验器，与 `planners-source-index` 的同名实现是**同一套写法**（约 35 行）。按「rule of three」暂时留着：出现**第三个**消费者时抽成公共件。抽之前不要在两边做不同的修改 —— 那样它们就不再是同一套了。
